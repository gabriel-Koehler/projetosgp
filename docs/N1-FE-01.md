# AvaliaSystem — N1-FE-01

## Executar
Requer Node.js 18 ou superior. Execute `npm install` e `npm start`.
Acesse http://localhost:3000. Desenvolvimento: `npm run dev`.
Neste ambiente Windows, se houver EPERM na resolução de caminhos, use:
`node --preserve-symlinks --preserve-symlinks-main server.js`.

Conta de demonstração: professor@avaliasystem.com / 123456.
Também é possível criar uma conta. Dados são separados por conta e vivem na memória
do processo: reiniciar o servidor restaura os exemplos.

## Escopo entregue
Layout baseado no PDF do Figma: marca AvaliaSystem, paleta verde, login dividido,
menu lateral, estados ativos, nome do professor, logout, rodapé e adaptação mobile.
Formulários com labels, foco visível, mensagens de erro, carregamento e prevenção
de envio duplicado. Navegação por hash mantém os links compartilháveis.

O MVP inclui cadastro de semestres, turmas e alunos, banco de questões com busca,
cadastro e exclusão, assistente de avaliações, versões embaralhadas, QR PNG,
correção por respostas informadas, estatísticas, CSV e impressão do relatório.

Google e recuperação de senha exibem explicitamente sua condição de simulação.
Leitura óptica/câmera, importação em lote, edição de cadastros, destinatário
individual, PDF de provas e exportação XLSX não fazem parte desta issue.
O MVP calcula notas; não realiza OMR nem envia mensagens.

## Integração
`public/api.js` centraliza fetch, timeout, cookies e erros.
`GET /config.js` fornece a base /api. O contrato HTTP usa:
- sucesso: { data: ... }
- falha: { error: { message: ... } }
- 400 validação, 401 sessão inválida, 404 recurso ausente e 409 duplicidade.

`src/mock-api.js` é o adaptador temporário para validar o front isoladamente.
A entrega N1-BE-02 substitui esse adaptador pelo serviço Python em uma branch derivada.
Ao trocar por uma API externa, preferir um proxy no mesmo domínio para preservar cookies
e implementar a verificação de sessão nas rotas de página conforme o provedor escolhido.

## Validação
`npm test` executa os testes de domínio e do contrato HTTP.
Se o sandbox Windows impedir o runner, executar individualmente:
`node --preserve-symlinks --preserve-symlinks-main tests/core.test.js`
`node --preserve-symlinks --preserve-symlinks-main tests/api.test.js`

Fluxo de navegador validado em 1600×900 e 390×844: login inválido/válido,
assistente, QR, correção, resultados, menu mobile e logout.
Teste HTTP cobre autorização, validação, isolamento de contas, ajuste de gabarito,
nota 10 com todas corretas e impedimento de correção duplicada.

Autenticação e armazenamento destinam-se a demonstração local, não a produção.
