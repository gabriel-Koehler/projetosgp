## Implementação

- O modo real disponibiliza Nova Avaliação e Versões & QR Code no visual AvaliaSystem existente. O assistente usa turmas e todo o banco paginado de questões da API persistente.
- Cadastro de questões no assistente preserva categoria e alternativa E opcional. A configuração envia IDs, nota máxima, gabarito específico da avaliação, quantidade de versões (1–500), nomes por letras/números/cores ou personalizados, conjuntos iguais/diferentes e embaralhamento de questões/alternativas. Até 100 questões selecionadas por avaliação.
- A API persistente inclui as camadas de avaliações do PR #43 do Luan, adaptadas à sessão e ao proxy desta sequência; sem merge da branch do colega. Criação grava avaliação, seleção, versões, snapshots e gabaritos em uma transação. Dados são filtrados pelo professor autenticado.
- A lista consulta os resumos gravados, e o detalhe recupera versões e questões do banco ao abrir a avaliação. Não regenera versões no navegador. Carregamento, erro e nova tentativa são apresentados, com proteção contra respostas que chegam após mudar de página.
- Snapshots preservam provas e gabaritos após editar ou arquivar questões do banco. Alterar o gabarito na avaliação não altera a questão original. Nomes vazios, repetidos ou inválidos são rejeitados na API.
- QR Codes usam o código aleatório persistido de cada versão e a origem pública do frontend, informada pelo proxy ou `PUBLIC_BASE_URL`. PNG exige autenticação do professor dono da avaliação.
- Prova, folha de respostas e gabarito consomem o detalhe persistido. A folha acomoda alternativa E e questões com quantidades distintas de alternativas.
- Liberação/revogação dos gabaritos ocorre para todas as versões da avaliação, conforme o contrato do backend; a interface explicita esse alcance. A tela pública devolve apenas nomes e letras corretas, sem dados de alunos, enunciados, notas ou respostas individuais.
- Rascunhos são separados por usuário e modo. O modo N1 permanece disponível; correção real e XLSX continuam na #28.

## Contratos principais

| Operação | Rota |
| --- | --- |
| Criar/listar | `POST/GET /api/avaliacoes` |
| Recuperar versões e snapshots | `GET /api/avaliacoes/{id}` |
| Liberar/revogar gabaritos | `PATCH /api/avaliacoes/{id}/gabarito` |
| QR autenticado | `GET /api/avaliacoes/{id}/versoes/{codigo}/qrcode.png` |
| Gabarito público, sujeito à liberação | `GET /api/public/gabaritos/{codigo}` |
| Tela do aluno | `/student?token={codigo}` |

## Execução e validação

Configure a conexão conforme [N2-FE-01](N2-FE-01.md), depois execute `npm run dev:real`. O Supabase existente de Diego é o projeto `projetosgp` (`veyofappfyaoejcjwxky`), documentado na branch `infra/diego-validacao-supabase`, PR #63 (depende de #61/#62). Sua conexão `.env.supabase.local` não versionada não está disponível neste workspace. Não é necessário provisionar outro projeto.

Em 2026-10-07:

- **194 testes Python e 17 testes JavaScript aprovados**, incluindo 11 novos testes de API de avaliações com PostgreSQL real descartável e quatro novos testes de contratos/configuração do frontend.
- Verificados persistência após recriar API/pool, snapshots após edição/arquivamento, gabarito específico da avaliação, conjuntos diferentes, nota máxima, isolamento de professores, filtros, QR decodificado, liberação/revogação e rollback após falha intermediária.
- Fluxo HTTP real pelo proxy Express, usando o próprio adaptador JavaScript da aplicação: login/cookie, cadastro/configuração, lista/detalhe, snapshot, PNG QR, páginas de impressão/aluno e gabarito mínimo. Reinício do processo Python preservou sessão, avaliações, versões e códigos.
- O fluxo HTTP usou o DDL exato de Diego em banco local separado, com RLS habilitada nas 12 tabelas e conexão pelo papel PostgreSQL local de teste. Isso não comprova permissões do papel remoto do backend.
- Sintaxe Python/JavaScript e `git diff --check` verificados.

Para repetir a suíte de banco, use exclusivamente um PostgreSQL descartável: os fixtures apagam e recriam o schema `public` quando `TEST_DATABASE_URL` e `ALLOW_TEST_DATABASE_RESET=1` estão definidos. Nunca configure a conexão Supabase de homologação nessa variável. Execute `python -m pytest -q` e `node --test`.
