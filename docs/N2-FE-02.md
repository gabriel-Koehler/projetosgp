# N2-FE-02 — Banco de questões e upload com API persistente

Issue #23. Branch `feat/n2-fe-02-integracao-questoes-upload`, criada a partir de `feat/n2-fe-01-integracao-auth-turmas` em `121fbdb`. Depende do PR #64 e, por ele, do PR #60. Os endpoints de questões reaproveitam o trabalho do PR #42, adaptado à aplicação persistente desta sequência.

## Implementação

- Banco de questões disponível em `npm run dev:real`, com cadastro, edição, filtros locais por texto/disciplina/dificuldade e exclusão ou arquivamento conforme os vínculos existentes.
- Carregamento paginado da API até recuperar todo o banco, incluindo questões além das primeiras 200. Identificadores numéricos são adaptados à interface existente.
- Questões importadas com alternativa E, categoria e dificuldade não informada podem ser editadas preservando esses campos.
- Upload multipart CSV/XLSX, até 5 MB e 5000 linhas. A API gera a prévia com alternativas, gabarito e mensagens por linha. A prévia não grava dados; a confirmação revalida duplicidades no banco e grava as linhas válidas em uma transação.
- Modelos CSV e XLSX fornecidos pela API autenticada. Cookies permanecem na mesma origem, pelo proxy Express; credenciais de banco não são enviadas ao navegador.
- Erros de validação, sessão e indisponibilidade usam o tratamento visual existente. Após falha de confirmação, exige nova prévia para reduzir o risco de repetir uma gravação cujo retorno se perdeu.
- Modo N1 em memória preservado. Avaliações persistentes e correção real permanecem para #25 e #28.

## Execução e aceite

Use a configuração e migração descritas em [N2-FE-01](N2-FE-01.md), depois `npm run dev:real` e Banco de Questões. Para aceite remoto, use um projeto Supabase de desenvolvimento autorizado: cadastre, edite, importe e recarregue os dados, confirmando-os no banco. A validação PostgreSQL local não substitui essa homologação.

Os testes de banco usam exclusivamente um PostgreSQL descartável, pois recriam o schema `public`:

```powershell
$env:TEST_DATABASE_URL = 'postgresql://postgres@127.0.0.1:55432/n2_issue23_test'
$env:ALLOW_TEST_DATABASE_RESET = '1'
python -m pytest -q
node --test
```

## Validação

- 183 testes Python aprovados em PostgreSQL 16.14 local, incluindo persistência após recriar a API/pool, isolamento entre professores, revalidação de duplicidades e rollback após falha intermediária.
- 13 testes JavaScript aprovados, incluindo paginação acima de 200 questões, contrato com alternativa E/categoria e multipart sem Content-Type JSON.
- Sintaxe Python/JavaScript e diff verificados.
- Fluxo HTTP real pelo proxy Express aprovado: login e cookie, painel/configuração, CRUD com E/categoria, modelos CSV/XLSX, upload multipart, prévia, confirmação, duplicadas e logout. API e banco locais descartáveis; isso não constitui validação visual em navegador.
- Pendências: homologação no Supabase de desenvolvimento e validação visual desktop/mobile. Nenhum navegador conectado disponível nesta sessão. Issue aberta; sem merge.
