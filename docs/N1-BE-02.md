## Executar no Windows
Na pasta desta cópia:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
npm install
npm run dev:all
```

No ambiente restrito usado para esta entrega, caso npm/Node retorne EPERM:
`node --preserve-symlinks --preserve-symlinks-main scripts/start-mvp.js`.

- Interface: http://localhost:3000
- API e Swagger: http://127.0.0.1:8000/docs
- Saúde: http://127.0.0.1:8000/health
- Conta: professor@avaliasystem.com / 123456

O launcher inicia os dois processos e encerra ambos com Ctrl+C.
Para executar separadamente:
`python -m uvicorn app.main:app --host 127.0.0.1 --port 8000`
e `npm start`, após ativar a venv.
Use um único worker: o armazenamento é em memória e não é compartilhado entre processos.

## Arquitetura
`app/mocks/data_provider.py` contém listas de semestres, turmas, alunos e
questões com alternativas A–D e gabarito. Cada professor recebe uma cópia
independente. Não há banco de dados ou arquivos de dados persistentes.

`app/main.py` fornece FastAPI, modelos de validação, sessões com expiração de
uma hora, geração de versões/QR e cálculo de notas. Senhas são derivadas com
PBKDF2 e salt; tokens de sessão ficam em cookies HttpOnly/SameSite.
Este é um serviço de desenvolvimento local, não autenticação pronta para produção.

`server.js` serve o front e encaminha /api ao Python. Nenhum mock Node é executado
nesta branch. O proxy mantém cookies no mesmo domínio.
`public/api.js` centraliza o contrato e traduz os nomes dos recursos para as rotas
em português. A tela carrega as coleções por essas rotas.

## Contrato HTTP
Todas as rotas de dados exigem sessão; login e cadastro retornam cookie de sessão.
Sucesso: `{ "data": ... }`. Erro: `{ "error": { "message": "..." } }`.
Status: 200/201 sucesso; 400 dados inválidos; 401 sessão ausente/expirada;
404 recurso não encontrado; 409 duplicidade; 502 no proxy quando Python indisponível.

| Recurso | Rotas |
| --- | --- |
| Sessão | POST /api/auth/login, /register, /logout; GET /api/auth/me |
| Recuperação simulada | POST /api/auth/recovery |
| Semestres | GET/POST /api/semestres |
| Turmas | GET/POST /api/turmas; filtro ?semestre_id=s1 |
| Alunos | GET/POST /api/alunos; filtro ?turma_id=c1 |
| Questões | GET/POST /api/questoes; filtro ?q=contrato; DELETE /api/questoes/{id} |
| Avaliações | GET/POST /api/avaliacoes |
| QR Code | GET /api/avaliacoes/{id}/qr/{versao} |
| Resultados | GET/POST /api/resultados |
| Snapshot opcional | GET /api/workspace |

Os campos JSON mantêm o contrato do front: semesterId, classId, statement,
options, answer etc. As rotas em inglês permanecem como aliases de compatibilidade.
O Swagger apresenta modelos, campos obrigatórios e exemplos de formatos.

## Regras verificadas
- Turma exige semestre existente; aluno exige turma e matrícula única.
- Questão exige 4 alternativas e resposta A–D; versões existentes preservam
  cópias das questões mesmo após exclusão no banco.
- Avaliação exige turma e questões existentes, sem repetição, e 1 a 5 versões.
- O embaralhamento preserva a alternativa correta pela identidade original.
- Correção exige aluno da turma, versão e uma resposta por questão.
- Nota = acertos / total × 10; apenas um resultado por aluno e avaliação.
- Cada conta vê exclusivamente seu estado; sessões expiram e logout invalida o token.

## API real depois
Troque API_TARGET do servidor web para a origem da API real (padrão:
http://127.0.0.1:8000). A API deve preservar rotas, payloads e cookies,
ou o adaptador em public/api.js deve traduzir o novo contrato.
O armazenamento em memória pode ser substituído por repositórios sem mudar as telas.

Google OAuth, envio de recuperação por e-mail e leitura OMR/câmera não são
executados. A interface informa a simulação. Importação em lote, edição completa
de cadastros, destinatário individual, PDF de prova e XLSX permanecem fora destas
duas issues. Há CSV de resultados e impressão pelo navegador.
